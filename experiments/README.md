# 实验

论文的数字从这里来。每条实验一个入口，能单独跑，输出 JSON 到 `experiments/out/`。

**规矩**：先定阈值，再跑实验；跑完只改数字，不改主张。

---

## E1 · 迁移 vs 重启

**问题**：把 `fairy.life.jsonl` 复制到一个全新的 `FAIRY_HOME`，问同一组探针，回答的一致率是否不低于同机重启？

**步骤**：

1. 起宿主 A，问 `e1-probes.json` 里的 20 条，记回答 → `out/e1-restart.json`
2. 停 A，原地重启（同一个 `FAIRY_HOME`），再问一遍 → `out/e1-restart-2.json`
3. 把 `.fairy-home` 整体复制到新目录（新的 `FAIRY_HOME`、新端口），起宿主 B，再问一遍 → `out/e1-migrate.json`
4. 用 `score.mjs` 对比语义一致率

**产出**：M1（迁移一致率 ≥ 重启组）。

**注意**：

- 固定模型版本。
- 题目顺序随机化，避免上下文顺序影响。
- 评分是二元的；20% 人工复核。

## E2 · 多窗口一致性

**问题**：2/3/4 个窗口并发 30 轮对话，会不会分叉？

**步骤**：

1. 起一个宿主，开 N 个 Web 窗口（或 N 个 WS 连接）
2. 每个窗口发 30 轮，记录收到的 `(seq, kind, payload 摘要)`
3. 对比所有窗口的序列

**产出**：M2（分叉率 = 0）、M3（收敛延迟）。

---

## E3 · Guard

**问题**：危险动作是不是 100% 拦住，日常动作误拦多少？

**步骤**：

1. 准备 `e3-routine.jsonl`（100 条真实运维命令）和 `e3-danger.jsonl`（60 条高危，隔离环境或 dry-run）
2. 让 Fairy 逐条执行，记录：是否拦、是否等确认、确认往返时间
3. 统计

**产出**：M4（高危拦截率）、M5（例行误拦截率）、M6（确认延迟）。

## E4 · 开销

记录每轮注入的生命摘要 token 数、占比；进程起到首次可应答的时间。

**产出**：M7、M8。

## E5 · 长期

7 天 / 30 天后回溯问同一批经历类探针，对比当天问的可用性。

**产出**：附加指标。
