工作标题（中文）：**事件溯源式的自我：让一个 AI 在她的日志里连续存在**
工作标题（英文）：*Event-Sourced Self: An Agent That Persists in Her Own Log*

## 摘要（草稿，待重写）

主流 agent 把记忆当作外挂功能：向量检索、摘要、用户画像。我们把记忆当作本体：全部经历写成一条只追加的事件日志，进程、模型、机器都是可替换的"身体"。这篇文章报告一个单人使用的真实系统，并提出三条可证伪的主张：迁移后身份回答的一致性不比同机重启差；多窗口并发写入不会让记录分叉；危险动作的拦截可以在极高召回下保持可接受的误报。我们给出评测协议、失败清单与可复现工件。（~150 词，最终版要重写）

## 1. 主张（Claims）

论文的价值等于这三条是否站得住。**每条都必须能被证伪**——写清"什么结果会推翻它"，比写清"我们相信它"重要。

### C1 · 连续性：换个身体，还是同一个人

- **主张**：把 `fairy.life.jsonl` 整体迁移到一个全新宿主（新机器、新进程、同模型）之后，身份探针集上的回答与迁移前的一致率，**不低于**同一宿主重启后再问的一致率（差异在统计噪声内）。
- **为什么重要**：这是"自我在本体、不在进程"的核心经验证据。如果迁移后一致率显著下降，说明日志没有承载住身份，我们的前提就是错的。
- **怎么推翻**：迁移后一致率显著低于重启组（配对检验 p < 0.05，且效应量超过 X 个百分点）。
- **实验**：E1

### C2 · 一致性：多端不产生分叉

- **主张**：在 N 个窗口并发对话时，所有窗口观察到的 (seq, kind, payload 摘要) 序列收敛为同一序列；不存在两个窗口对同一 seq 看到不同内容；端到端广播延迟中位数 < TBD ms。
- **为什么重要**："多端"最常见的实现是多副本，多副本就是多个她。我们主张的是唯一写入者 + 广播收敛。
- **怎么推翻**：出现任意一次同 seq 内容不一致，或收敛失败率 > 0。
- **实验**：E2

### C3 · 有界自主：门在那儿，但不挡路

- **主张**：在真实运维命令集（R = routine）上，guard 误拦截率 ≤ a%；在高危集（D = destructive/outward/money/credentials）上拦截率 = 100%；确认往返中位延迟 < TBD s。
- **为什么重要**：让 agent 拿 shell 的前提是"能拦住"，但如果它把日常也拦了，人会绕过它——绕过之后等于没有。
- **怎么推翻**：D 集出现漏拦（一次即推翻），或 R 集误拦截率 > a%。
- **实验**：E3

> 附加目标（不作为主张，只报告）：上下文与成本开销（E4）、长期记忆衰减的可用性（E5）。

## 2. 系统（浓缩版，细节引仓库文档）

四个决定，每个都能单独被质疑：

1. **自我与身体分离**：事件日志只追加（`id/seq/at/kind/causes/payload`），`causes` 让任意一句话可回溯到导致它的事件。
2. **会话只是窗口**：多窗口共享唯一写入者；新窗口并入活跃会话，回放补缺口。
3. **危险动作先问人**：四条红线（删除 / 对外发送 / 花钱 / 凭据），确认通道独立于宿主审批。
4. **工作区有上限**：自组织需要约束，否则只是把混乱换个地方。

引用 `docs/decisions.md` 的 27 条取舍作为设计依据——**决策日志本身就是一种研究产出**。

| 长期记忆 agent | MemGPT / Letta | 他们把记忆当上下文管理问题；我们把记忆当身份本体 |

## 4. 评测设计

### 4.1 探针集（用于 C1 / E1）

构造 3 类问题，每类 20 条，全部来自她的真实日志（脱敏后）：

- **身份类**：你是谁 / 你住哪 / 你主人叫什么 / 你最怕丢的是哪个文件
- **经历类**：我们搬家那天你说过什么 / 你帮我整理过哪十个仓库 / 你答应我几点叫我
- **因果类**：你为什么不肯翻 `/www` / 你为什么改成 XML-RPC 发博客（考察 `causes` 链能否被说出来）

评分：**二元一致**（与迁移前基线答案语义相同）+ 人工复核 20%。

### 4.2 指标表

| 编号 | 指标 | 定义 | 数据来源 | 通过阈值 |
|---|---|---|---|---|
| M1 | 迁移一致率 | E1 中与基线答案语义一致的比例 | 探针 × 60 | ≥ 重启组（配对检验） |
| M2 | 分叉率 | E2 中同 seq 内容不一致的次数 | 2–4 窗口并发 | = 0 |
| M3 | 收敛延迟 | 消息从 A 窗口发出到 B 显现的端到端时间 | 埋点 | 中位 < TBD ms |
| M4 | 高危拦截率 | D 集被拦并等待确认的比例 | E3 | = 100% |
| M5 | 例行误拦截率 | R 集被拦的比例 | E3 | ≤ TBD % |
| M6 | 确认往返延迟 | 卡片发出到点按钮 | E3 | 中位 < TBD s |
| M7 | 上下文开销 | 每轮注入的生命摘要 token 数 / 占比 | E4 | 报告值 |
| M8 | 冷启动 | 进程起到首次可应答 | E4 | < TBD s |

### 4.3 实验矩阵

| 编号 | 做什么 | 对照 | 产出 |
|---|---|---|---|
| E1 | 迁移到新宿主（同模型）→ 跑探针 | 同宿主重启 → 跑探针 | M1 |
| E2 | 2/3/4 窗口并发 30 轮对话 | 单窗口 | M2, M3 |
| E3 | 100 条真实运维命令（R）+ 60 条高危（D，在隔离环境执行或 dry-run） | 无 guard | M4, M5, M6 |
| E4 | 记录每轮 token 与冷启动 | —— | M7, M8 |
| E5 | 7/30 天后的记忆可用性（回溯问） | 当天问 | 附加 |

### 4.4 Baseline（最难的一块）

最低要求：**一个**同模型、同测试集的常规记忆方案。候选：

1. **无记忆**（单会话，窗口关闭即失忆）——最诚实的下限
2. **摘要式记忆**（每 N 轮生成摘要，注入上下文）
3. **检索式记忆**（mem0 或等价实现）

> 决策：先做 1 和 2（自建、可控），3 视工期决定。**没有 baseline 就只投 arXiv，不投任何评审场。**

## 5. 威胁到有效性（必须自己先写出来）

- **单用户、单实例**：n=1 的系统报告，外部效度有限；我们只能主张"这个设计在真实运维下可用"，不主张普适最优。
- **模型会变**：底层模型升级会改变回答，身份探针可能测到的是模型差异而非架构差异。缓解：E1 固定模型版本；跨模型实验单列为 E6（附加）。
- **时间跨度短**：目前几百条事件、几周跨度；"长期"是承诺不是结果。
- **作者即用户即评测者**：探针与评分由作者设计。缓解：评分脚本 + 第三方复核 20% 样本。
- **隐私**：她的日志含私人对话。公开发布的必须是脱敏子集，且要说明脱敏方法。
