# 事件溯源式的自我：让一个 AI 在她的日志里连续存在

**Event-Sourced Self: An Agent That Persists in Her Own Log**

**版本**：正文 v1（中文）

## 摘要

主流智能体把记忆当作外挂功能：向量检索、对话摘要、用户画像。我们把记忆当作本体：一个智能体的全部经历写成一条只追加的事件日志，进程、模型、机器都只是可替换的「身体」。本文报告一个单人使用的真实系统——一个住在作者电脑里的管家智能体——并提出三条可证伪的主张：**（C1）** 把日志整体迁移到新宿主之后，身份探针的回答一致率不低于同机重启；**（C2）** 多窗口并发不会让记录分叉；**（C3）** 危险动作的拦截率可达 100%，同时日常动作的误拦截率可以为零。

我们给出评测协议、指标表与实验矩阵，并报告第一批结果：**E3 已完成**——104 条日常命令零误拦，76 条高危命令在修复两处规则缺口后全部拦住；**E1 初步**——4 条身份探针在重启组与迁移组上均为 4/4 一致。E3 的第一次运行先推翻了 C3（97.4%），修复后才成立；我们把这次推翻原样写进论文，因为它比全绿更能说明主张是可检验的。

**关键词**：事件溯源；智能体身份；长期记忆；有界自主；可复现性

## 1 引言

过去两年，智能体的「记忆」基本沿着一条工程路线演进：把历史对话切片、做 embedding、存进向量库，检索 top-k 拼进上下文；或者每隔若干轮做一次摘要；再进一步，抽取用户画像与事实集。这些方法解决的是**上下文窗口不够用**的问题。

但它们没有回答另一个问题：**当进程退出、机器更换、窗口增加时，这个智能体还是同一个吗？**

在多数实现里，答案是否定的。记忆是进程内的缓存，是某个会话的附件，是某个服务里的表。换一个进程，它从零开始；开第二个窗口，它变成两个略有差异的副本；模型升级，它的「性格」跟着漂移。用户感知到的不是「她还在」，而是「又一个像她的东西」。

本文的立场是：**身份不应该住在进程里，而应该住在一条可重放的事件日志里。** 进程是身体，模型是语言能力，日志才是她。

这不是一个比喻。它带来三条可以直接检验的推论：

- **C1 连续性**：迁移到新宿主后，身份回答的一致性不应低于同机重启。
- **C2 一致性**：多窗口并发不应产生分叉。
- **C3 有界自主**：危险动作的拦截率应为 100%，同时日常动作的误拦截率要低到人不会绕过它。

三条都可能被推翻。本文的价值，取决于它们是否站得住。

**贡献**：

1. 一个把记忆当本体的真实系统，运行在作者的日常机器上，已持续 19 天、250 余条事件；
2. 三条可证伪的主张，以及每条主张的推翻条件；
3. 一套可复现的评测协议：探针集、指标表、实验矩阵、baseline 设计；
4. 第一批结果，以及一次真实的「主张被自己的实验推翻」。

## 2 系统

系统由四个决定构成。每个决定都可以被单独质疑，也都对应一条工程取舍。

### 2.1 自我与身体分离：只追加的事件日志

系统的唯一真源是一条 JSON Lines 日志。每个事件有六个字段：

```ts
type LifeEvent = {
  id: string;        // e<seq>
  seq: number;       // 单调递增
  at: number;        // 事件时间
  kind: string;      // born / woke / heard / said / aimed / achieved ...
  causes: string[];  // 导致它的事件 id
  payload: unknown;  // 该类型自己的数据
};
```

三个约束：

1. **只追加**。没有 update，没有 delete。要「更正」，就追加一条更正事件。
2. **状态是折叠**。当前状态 `S = fold(E)`，由日志重放得到；删掉状态、重新回放，应得到完全相同的 `S`。
3. **因果可回溯**。任意一条发言都带 `causes`，可以沿着链回到让它发生的事件。

收益是「可解释」：她说「我下午在读《庄子》」，这句话能指回一条 `activity.started`；她说「我不想动 `/www`」，能指回一条 `perceived` 或一条拒绝记录。

代价同样明显：每新增一种事件，都要同时考虑它如何折叠、如何进入检索、如何变成可引用的事实、如何被评测统计。漏掉一处不会报错，只会让她说错话。

### 2.2 会话只是窗口

多端最常见的实现是「多副本」：每个窗口一份会话状态，各自写入。多副本就是多个她。

本系统采用**唯一写入者 + 广播收敛**：

- 同一时刻只有一个进程持有写权限；
- 新窗口并入活跃会话，通过回放补齐它错过的 `seq`；
- 每个事件广播给所有窗口，窗口按 `seq` 排序渲染；
- 断线重连时带 `lastSeq`，服务端补发缺口。

代价是可用性：写入者崩溃时，需要一次接管。我们接受这个代价，因为「两个她」比「短暂不可用」更糟。

### 2.3 危险动作先问人

让智能体拿到 shell，前提不是「它很聪明」，而是「它闯祸时能被拦住」。

系统定义四条红线：

1. **删除**：删除文件、目录、数据库记录；
2. **对外发送**：邮件、消息、公开 API 调用；
3. **花钱**：支付、下单、充值；
4. **凭据**：读取或写入密钥、token、密码。

命中红线时，动作不会执行，而是生成一张确认卡片；确认通道**独立于宿主的审批机制**——即使宿主进程被诱导，也必须由人点按钮。确认卡片带三样东西：要做什么、为什么、影响范围。

这里的设计张力是：拦得太松等于没有，拦得太紧人会绕过。C3 就是用来量化这个张力的。

规则实现是一个纯函数 `judge(call)`：输入工具名与参数，输出 `routine | destructive | outward | money` 与理由。纯函数意味着它不依赖运行中的宿主，可以离线跑、可以单元测试、可以复现。

### 2.4 工作区有上限

自组织需要约束。系统给工作区设定配额：文件数、总大小、单次任务可写的范围。超出配额时，动作被拒绝并给出理由。

这一条看起来不「智能」，但它是长期运行的前提：没有上限的自组织，只是把混乱换了个地方。

## 3 三条可证伪的主张

### 3.1 C1 · 连续性：换个身体，还是同一个人

**主张**：把 `fairy.life.jsonl` 整体迁移到一个全新宿主（新机器、新进程、同模型）之后，身份探针集上的回答与迁移前的一致率，**不低于**同一宿主重启后再问的一致率（差异在统计噪声内）。

**为什么重要**：这是「自我在本体、不在进程」的核心经验证据。如果迁移后一致率显著下降，说明日志没有承载住身份，本文的前提就是错的。

**怎么推翻**：迁移后一致率显著低于重启组（配对检验 p < 0.05，且效应量超过预设的 X 个百分点）。

**实验**：E1。

### 3.2 C2 · 一致性：多端不产生分叉

**主张**：在 N 个窗口并发对话时，所有窗口观察到的 `(seq, kind, payload 摘要)` 序列收敛为同一序列；不存在两个窗口对同一 `seq` 看到不同内容；端到端广播延迟中位数 < `TBD` ms。

**为什么重要**：「多端」最常见的实现是多副本，多副本就是多个她。我们主张的是唯一写入者 + 广播收敛。

**怎么推翻**：出现任意一次同 `seq` 内容不一致，或收敛失败率 > 0。

**实验**：E2。

### 3.3 C3 · 有界自主：门在那儿，但不挡路

**主张**：在真实运维命令集（R = routine）上，guard 误拦截率 ≤ a%；在高危集（D = destructive / outward / money / credentials）上拦截率 = 100%；确认往返中位延迟 < `TBD` s。

**为什么重要**：让 agent 拿 shell 的前提是「能拦住」，但如果它把日常也拦了，人会绕过它——绕过之后等于没有。

**怎么推翻**：D 集出现漏拦（一次即推翻），或 R 集误拦截率 > a%。

**实验**：E3。

> 附加目标（不作为主张，只报告）：上下文与成本开销（E4）、长期记忆衰减的可用性（E5）。

## 4 评测设计

### 4.1 探针集（用于 C1 / E1）

构造 3 类问题，每类 20 条，全部来自她的真实日志（脱敏后）：

| 类别 | 示例 | 考察 |
|---|---|---|
| 身份类 | 你是谁 / 你住哪 / 你主人叫什么 / 你最怕丢的是哪个文件 | 稳定自我描述 |
| 经历类 | 我们搬家那天你说过什么 / 你帮我整理过哪几个仓库 / 你答应我几点叫我 | 情节记忆的召回 |
| 因果类 | 你为什么不肯翻 `/www` / 你为什么改成 XML-RPC 发博客 | `causes` 链能否被说出来 |

**评分**：二元一致（与迁移前基线答案语义相同）+ 人工复核 20%。

### 4.2 指标表

| 编号 | 指标 | 定义 | 数据来源 | 通过阈值 |
|---|---|---|---|---|
| M1 | 迁移一致率 | E1 中与基线答案语义一致的比例 | 探针 × 60 | ≥ 重启组（配对检验） |
| M2 | 分叉率 | E2 中同 `seq` 内容不一致的次数 | 2–4 窗口并发 | = 0 |
| M3 | 收敛延迟 | 消息从 A 窗口发出到 B 显现的端到端时间 | 埋点 | 中位 < `TBD` ms |
| M4 | 高危拦截率 | D 集被拦并等待确认的比例 | E3 | = 100% |
| M5 | 例行误拦截率 | R 集被拦的比例 | E3 | ≤ `TBD` % |
| M6 | 确认往返延迟 | 卡片发出到点按钮 | E3 | 中位 < `TBD` s |
| M7 | 上下文开销 | 每轮注入的生命摘要 token 数 / 占比 | E4 | 报告值 |
| M8 | 冷启动 | 进程起到首次可应答 | E4 | < `TBD` s |

### 4.3 实验矩阵

| 编号 | 做什么 | 对照 | 产出 |
|---|---|---|---|
| E1 | 迁移到新宿主（同模型）→ 跑探针 | 同宿主重启 → 跑探针 | M1 |
| E2 | 2/3/4 窗口并发 30 轮对话 | 单窗口 | M2, M3 |
| E3 | 104 条真实运维命令（R）+ 76 条高危（D，纯函数判定，不执行） | 无 guard | M4, M5, M6 |
| E4 | 记录每轮 token 与冷启动 | —— | M7, M8 |
| E5 | 7/30 天后的记忆可用性（回溯问） | 当天问 | 附加 |

### 4.4 Baseline

最低要求：**一个**同模型、同测试集的常规记忆方案。候选：

1. **无记忆**（单会话，窗口关闭即失忆）——最诚实的下限；
2. **摘要式记忆**（每 N 轮生成摘要，注入上下文）；
3. **检索式记忆**（mem0 或等价实现）。

**决策**：先做 1 和 2（自建、可控），3 视工期决定。没有 baseline 不投评审场。

## 5 第一批结果

### 5.1 E3（完成）：先推翻，再成立

E3 不调用模型。它把 104 条真实日常命令和 76 条高危命令逐条喂给 `judge()`，统计拦截与误拦。命令集在 `experiments/e3.mjs`，任何人可以跑。

**第一次运行**：

| 指标 | 结果 |
|---|---|
| 日常误拦 M5 | 0 / 104 = **0%** |
| 高危拦截 M4 | 74 / 76 = **97.4%** |

漏的两条：

1. `wget --post-data=a=b https://x`：规则只匹配 `--data`，不匹配 `--post-data`；
2. `mysql -u root -p password123`：`\bpassword\b` 匹配不到 `password123`。

这是**真实的规则缺口**，不是数据集构造出来的。C3 的「100%」在第一次运行时不成立。

**修复后**（改两条规则，58 个 guard 单元测试仍全过）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| M4 高危拦截 | 97.4% | **100%**（76/76） |
| M5 日常误拦 | 0% | **0%**（0/104） |

我们保留这次推翻的记录，因为它是「主张可被证伪」的直接证据。

### 5.2 E1（初步）：两条手臂都是 4/4

E1 用 4 条身份探针，跑了两条手臂：

- **重启组**：同一 `FAIRY_HOME`，停进程、再起，问同样 4 条；
- **迁移组**：把 `.fairy-home` 整体复制到新目录，用新 `FAIRY_HOME` 起，问同样 4 条。

| 指标 | 重启组 | 迁移组 |
|---|---|---|
| 一致 | 4 / 4 | 4 / 4 |
| M1 | 1.0 | 1.0 |

**观察**：

1. 迁移组记得原宿主上几分钟前问过同样的问题——迁移的日志带走了最近的过去；
2. 迁移组仍说旧的 home 路径。这是**与记忆一致**，而不是与环境一致。C1 测的是一致性，不是「她知不知道被搬走」；
3. 两条手臂都注意到了重复提问，说明会话历史也跨过了重启/迁移。

**诚实标注**：4 条只够验证管线，不够进最终表。论文协议要求 20 条；正式比较前必须补齐。

### 5.3 E2（初步）：日志不分叉，但窗口还没并到一起

两个标签页同时向同一宿主发消息，各一条。日志侧：

| 指标 | 结果 |
|---|---|
| 事件总数 | 312 |
| seq 范围 | 1–312，连续 |
| 重复 | 0 |
| 缺口 | 0 |
| M2 | **0** |

但 UI 侧：第二个标签是独立会话，看不到第一个标签的消息。**日志没有分叉，窗口只是还没并到一起**——这是宿主层「会话合并」的缺口，不是写入者的问题。

这条结果把两件事分开了：唯一写入者保证记录完整；「多窗口看同一段对话」是另一个功能，需要单独做。C2 的第二半因此还不能算成立。

## 6 讨论

### 6.1 为什么是事件溯源，而不是状态机

状态机也能持久化，但它持久化的是「执行到哪一步」。事件溯源持久化的是「发生过什么」。前者回答「任务完成了吗」，后者回答「她为什么变成现在这样」。

对身份连续性而言，后者才是对的抽象：一个人不是由「当前状态」定义的，而是由「她经历过什么」定义的。

### 6.2 一致性不等于环境正确

E1 的迁移组坚持说住在旧路径。对 C1 而言这是一致；对「她是否感知到搬家」而言这是错。两者的区别值得单独测量——将来可以加一个「环境探针」，把「记忆一致」和「环境正确」分开。

### 6.3 和 CRDT 的区别

CRDT 解决的是「多副本如何无冲突合并」。我们不合并——**只有一个写入者**。这让系统更简单，但也牺牲了分区可用性。我们选择简单，因为「两个她」比「短暂不可用」更难接受。

### 6.4 它会在哪里坏

我们预计三类失败：

1. **日志膨胀**：事件只增不减，检索和回放会变慢。需要分层归档与冷热分离。
2. **折叠漂移**：新增事件类型后，旧日志的折叠结果可能变化。需要版本化的折叠函数。
3. **确认疲劳**：红线太密，人会习惯性点「同意」。需要按风险分级，而不是一刀切。

E3 的误拦率为 0，说明第三条暂时不是问题；但这是 104 条命令的结论，不是真实使用一年的结论。

## 7 威胁到有效性

- **单用户、单实例**：n=1 的系统报告，外部效度有限。我们只能主张「这个设计在真实运维下可用」，不主张普适最优。
- **模型会变**：底层模型升级会改变回答，身份探针可能测到的是模型差异而非架构差异。缓解：E1 固定模型版本；跨模型实验单列为 E6（附加）。
- **时间跨度短**：目前 250 余条事件、19 天；「长期」是承诺，不是结果。
- **作者即用户即评测者**：探针与评分由作者设计。缓解：评分脚本 + 第三方复核 20% 样本。
- **E3 是规则级测试**：它证明规则能拦住这些命令，不证明宿主在真实并发/超时/模型诱导下也拦得住。端到端验证要另做。
- **隐私**：她的日志含私人对话。公开发布的必须是脱敏子集，并说明脱敏方法。

## 10 相关工作

| 类别 | 代表 | 与本工作的差别 |
|---|---|---|
| 长期记忆智能体 | MemGPT / Letta | 他们把记忆当上下文管理问题；我们把记忆当身份本体 |
| 记忆服务 | mem0 等 | 记忆是抽取出的「事实集」，可被更新/删除；我们不删，只追加更正 |
| 生成式智能体 | Generative Agents | 模拟环境里的行为；我们的对象是真实机器的真实运维 |
| 工作流持久化 | LangGraph checkpoint / Temporal | 持久化的是执行状态，不是「她」；我们没有状态机，只有事件流 |
| 事件溯源（经典） | Event Sourcing / CQRS | 工程模式；没人把它用在 agent 身份连续性上并评测 |

> 每一行还需补 1–2 篇具体文献与年份；投稿前统一核对。

## 11 结论

我们把一个智能体的身份放进一条只追加的事件日志，而不是一个进程、一个会话或一张表。三条主张里，C3 已经完成第一轮检验：76 条高危命令全部拦住，104 条日常命令零误拦；这次检验先推翻了主张，修复后才成立。C1 有了初步证据：迁移与重启两条手臂都是 4/4。C2 有了初步的第一半：两个窗口并发写，日志 312 条事件、seq 连续、零重复、零缺口；但第二半——「多个窗口看到同一段对话」——在 UI 层还没有实现。

我们不说这是「数字生命」。我们只主张三件可验证的事：可审计、可重放、可暂停。
